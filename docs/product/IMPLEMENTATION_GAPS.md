# Product requirements versus the existing prototype

Assessment date: 2026-11-06 (originally 2026-10-30). This maps the existing source and verification reports to the broader product definition, updated with the [ENT-01 implementation and current test evidence](../PROGRAM_IMPORT.md#verified-on-2026-10-30).

| Requirement | Existing evidence | Remaining work |
| --- | --- | --- |
| ENT-01 variable plans | Variable library with JSON preview/save, ordered blocks/weeks/days/exercises/sets, stable IDs, independent atomic persistence; saved days are now trained directly (ENT-04) and re-imports are idempotent (ENT-09) | Closed 2026-11-07 with emulator-only evidence; target-phone acceptance waived by the user. See [import contract](../PROGRAM_IMPORT.md) |
| ENT-02 JSON exchange | Typed context/proposal/results v1; review/save, copy/file export, independent atomic archive, strict compatibility and round-trip checks; see [contract](../JSON_EXCHANGE.md) | ENT-02 delivery accepted with emulator evidence; physical testing waived by user on 2026-10-30. Proposal activation and real history remain separate requirements |
| ENT-03 Markdown migration | Workout v3 parser; original/source lines, separate objectives/results, ambiguity review and independent atomic offline archive; see [contract](../OBSIDIAN_MIGRATION.md) Reviewed migrations convert into program weeks with exact values only ([conversion](../OBSIDIAN_MIGRATION.md#converting-a-saved-migration-into-a-program-week)); recorded results are not yet converted into session history. Delivery acceptance is emulator-only by user selection |
| ENT-04 one-tap overlay | Saved program days load as sessions; overlay/notification record a prefilled set in one tap with immediate persistence; finished/closed sessions archived; see [planned recording](../PLANNED_RECORDING.md) | Target-phone validation of permissions, accessibility and interruptions; emulator-only evidence |
| ENT-05 actual versus planned | Planned sessions keep the prescription in the plan snapshot; omit, add/remove extra and edit recorded sets with notes; stale-edit protection; v1 export as OMITTED/unprescribed; see [planned recording](../PLANNED_RECORDING.md#deviations-ent-05) | Edit audit trail kept per set (replaced versions, capped at 50) and shown in session history, but not exported in interchange v1; target-phone validation; emulator-only evidence |
| ENT-06 real sessions | Warm-up sets, pause/resume with exact rest shifting, cardio entries, active time and partial sessions for planned days; force-stop restore verified; see [planned recording](../PLANNED_RECORDING.md#real-sessions-warm-ups-pauses-and-cardio-ent-06) | Cardio cannot be prescribed in program v1; target-phone validation; emulator-only evidence |
| ENT-07 offline persistence | Atomic write-before-publish snapshots for session and history; no network permission; corrupt files never reset; crash-loop force-stop check in airplane mode; see [decision 0005](../architecture/decisions/0005-offline-persistence.md) | Room deferred to queryable history (ANA-01); target-phone validation; emulator-only evidence |
| ENT-08 exercise catalog | Stable-ID catalog with renames kept as aliases, movement/variant/equipment, informative load basis and setup notes; history by ID survives renames; indistinguishable labels rejected; see [catalog](../EXERCISE_CATALOG.md) | Catalog is not yet exported in interchange v1; target-phone validation; emulator-only evidence |
| ENT-09 validation and idempotency | Strict typed validation of all contracts; deterministic re-import plan shown before saving: identical no-op, new weeks appended without duplicates, conflicts listed by path with nothing written; see [import rules](../PROGRAM_IMPORT.md#re-import-and-merge-rules-ent-09) | Interchange proposals still archive as whole packages (approval flow is AG-02); target-phone validation; emulator-only evidence |
| Session history (follow-up) | Read-only list of recorded sessions, newest first, with status by the adherence categories, active time, set and cardio breakdowns, and a per-session detail of each set with notes, edit marks and previous versions; CSV export of all sessions ([columns](../SESSION_HISTORY_CSV.md)) | Target-phone validation; emulator-only evidence |
| ANA-01 exposures | Per-exercise exposures across weeks and programs by stable ID, grouped by unit and load basis (never mixed), with date, program/week/day, sets, top load, reps and RIR; see [exposure comparison](../EXPOSURE_COMPARISON.md) | Target-phone validation; emulator-only evidence |
| ANA-02 charts | Per unit/basis charts of top load, reps, volume and minimum RIR; omitted-only exposures are gaps, not zeros; user-marked deload weeks drawn distinctly; see [charts](../PERFORMANCE_CHARTS.md) | Target-phone validation; emulator-only evidence |
| ANA-03 body measurements | Dated measurements with metric, unit and mandatory method plus optional context; trends per metric+unit+method with a warning when methods or units are mixed; see [measurements](../BODY_MEASUREMENTS.md) | Export in interchange (v1 has no method field); target-phone validation; emulator-only evidence |
| ANA-04 adherence | Completed / partial / not performed / no record per planned day with set breakdowns; explicit not-performed marks; optional weekly session and cardio goals; see [adherence](../ADHERENCE.md) | Cardio cannot be prescribed in program v1; target-phone validation; emulator-only evidence |
| ANA-05 phase comparisons | Week rows per exercise and unit group, filterable by program and block (phase); deltas vs the previous comparable non-deload week; deloads listed but never compared; see [phase comparison](../PHASE_COMPARISON.md) | Phases are blocks (program v1 has no phase field); target-phone validation; emulator-only evidence |
| AG-02, AG-05, AG-06 proposal cycle | Proposals stay pending until explicit approval; configurable deterministic rules with blocks/warnings; computed changes vs. base week; approval appends the week idempotently; decision records; see [proposal review](../PROPOSAL_REVIEW.md) | Target-phone validation; emulator-only evidence |
| AG-03, AG-07 decisions and explanations | Changes classified as increase/reduction/substitution/addition/removal with on-device evidence and the agent's matching reason (never invented); unexplained-change rule; decisions store explanations; decision history; see [proposal review](../PROPOSAL_REVIEW.md#explained-changes-ag-07) | Target-phone validation; emulator-only evidence |
| AG-04 later evaluation | Expected results per approved recommendation (exercise, metric, direction, window); automatic favorable / unfavorable / inconclusive / pending against observed exposures excluding deloads; labelled manual override; see [proposal review](../PROPOSAL_REVIEW.md#later-evaluation-of-recommendations-ag-04) | Target-phone validation; emulator-only evidence |
| AG-01 focused questions | Planning gaps (goal, phase, restrictions, availability, unknown equipment) answered or marked not available; never invented, never blocking; answers feed exported context phase/goals/rules with explicit unknowns; see [proposal review](../PROPOSAL_REVIEW.md#focused-planning-questions-ag-01) | Target-phone validation; emulator-only evidence |
| INT-03 stagnation signals | Per exercise and unit group: no improvement over the pre-window best across N comparable non-deload exposures spanning a minimum period; each alert lists period, data used, limitations and explanation; insufficient evidence reported, never alerted; see [signals](../STAGNATION_SIGNALS.md) | Target-phone validation; emulator-only evidence |
| INT-01 MCP server | Stdio MCP server: reads only the user-exported context file, writes validated v1 proposals to an outbox, has no approval tool; app decodes and validates its output; see [MCP server](../MCP_SERVER.md) | Remote deployment needs authenticated sync (INT-02); file transfer is manual |
| INT-02 authenticated sync | Pairing keys; HMAC-SHA256 signed envelopes from the MCP server; app accepts only verified week proposals (key, signature, type, age, nonce), still pending approval; replay and conflict never overwrite data; relay transport designed in [decision 0008](../architecture/decisions/0008-authenticated-sync.md); see [signed sync](../SIGNED_SYNC.md) | Network relay not enabled (no network permission by decision 0005); emulator-only evidence |

Evidence: [prototype README](../../README.md), [verification report](../VERIFICATION.md), [latency investigation](../NOTIFICATION_LATENCY.md), and source under `app/src/`.

Status on 2026-11-07: every requirement is implemented, merged and closed in GitHub, with emulator-only evidence; physical Samsung/One UI testing was not performed for any of them. ENT-01 was closed on 2026-11-07 after the user waived its target-phone manual acceptance, as for ENT-02. Follow-ups since then (PRs #49–#54): session history with CSV export and program filter, a per-set edit audit trail, Obsidian-to-program conversion and device-test hardening. Deliberate limits that remain: program v1 has no cardio or phase fields; the sync relay is designed but not enabled (no network permission, decisions 0005 and 0008); Room is deferred to queryable history (decision 0005). GitHub Issues remain the source of execution status. Emulator verification is distinct from target physical-device verification. Recommendation outcome tracking concerns workout decisions, not training, fine-tuning, benchmarking, or evaluating AI models.
